## Problematic Pipelines

These pipelines contain intentional issues for learning and testing the analyzer.

### 1. hardcoded-secrets.yml

**Violations:**
- SEC-001: Hardcoded secrets in variables
- Passwords, API keys, and connection strings in plain text
- Secrets used directly in scripts

**Expected Score:** ~30/100

**How to analyze:**
```bash
node dist/cli/pipeline-assistant.js analyze -f docs/examples/problematic/hardcoded-secrets.yml
```

---

### 2. missing-security-stage.yml

**Violations:**
- POL-001: Missing mandatory security stage
- No TruffleHog secret scanning
- No SAST (SonarQube)
- No dependency scanning (Snyk)

**Expected Score:** ~40/100

**How to analyze:**
```bash
node dist/cli/pipeline-assistant.js analyze -f docs/examples/problematic/missing-security-stage.yml
```

---

### 3. no-cache.yml

**Violations:**
- PERF-001: No cache configuration
- Dependencies installed multiple times without caching
- Slow build times

**Expected Score:** ~60/100

**How to analyze:**
```bash
node dist/cli/pipeline-assistant.js analyze -f docs/examples/problematic/no-cache.yml
```

---

### 4. no-coverage.yml

**Violations:**
- QUAL-001: Tests without coverage reporting
- No PublishTestResults task
- No PublishCodeCoverageResults task
- No quality gates

**Expected Score:** ~55/100

**How to analyze:**
```bash
node dist/cli/pipeline-assistant.js analyze -f docs/examples/problematic/no-coverage.yml
```

---

### 5. no-approvals.yml

**Violations:**
- POL-002: No approval gates for production
- Direct deploy without manual validation

- No smoke tests

**Expected Score:** ~50/100

**How to analyze:**

## Usage in Workshop

### Exercise: Compare Problematic vs Correct

```bash
# Analyze problematic pipeline
node dist/cli/pipeline-assistant.js analyze -f docs/examples/problematic/hardcoded-secrets.yml

# Analyze correct pipeline
node dist/cli/pipeline-assistant.js analyze -f docs/examples/correct/dotnet-basic.yml

# Compare the scores and violations
```

### Exercise: Generate and Compare

```bash
# Generate a new pipeline
node dist/cli/pipeline-assistant.js generate \
  --platform azure-devops \
  --type dotnet \
  --output my-pipeline.yml

# Compare with the reference
diff my-pipeline.yml docs/examples/correct/dotnet-basic.yml
```

### Exercise: Fix Problematic Pipeline

1. Open `problematic/hardcoded-secrets.yml`
2. Identify all hardcoded secrets
3. Replace with variable group references
4. Add Key Vault task for secret management
5. Re-analyze to verify score improvement

## Regenerating Examples

The correct examples were generated using:

```bash
# Basic .NET
node dist/cli/pipeline-assistant.js generate \
  --platform azure-devops \
  --type dotnet \
  --output docs/examples/correct/dotnet-basic.yml

# Production .NET with services
node dist/cli/pipeline-assistant.js generate \
  --platform azure-devops \
  --type dotnet \
  --services redis,azuresql \
  --env prod \
  --output docs/examples/correct/dotnet-production.yml

# Basic Node.js
node dist/cli/pipeline-assistant.js generate \
  --platform azure-devops \
  --type node \
  --output docs/examples/correct/node-basic.yml

# Basic Python
node dist/cli/pipeline-assistant.js generate \
  --platform azure-devops \
  --type python \
  --output docs/examples/correct/python-basic.yml
```
